# T1.3 — SDL2 input

- agent: agent-06 (DeepSeek V4.1 Flash)
- date: 2026-10-31
- command: `docker run … openmt2/client:latest -t --skip-pack` + `scripts/golden-check.sh` + `grep -rn "DirectInput8Create" src` + `x86_64-w64-mingw32-g++ -c Input.cpp`
- before:
  - `EterLib/src/Input.cpp` kept the DirectInput device path in `#else`: `CInputDevice::CreateDevice` called `DirectInput8Create`, `CInputKeyboard` acquired a `LPDIRECTINPUTDEVICE8` and read `GetDeviceState`, and the SDL branch polled a hand-written list of **44 keys** (W/A/S/D/Q/E/R/F, digits, F1–F4, navigation, modifiers). Everything else — G..P, T..Z, punctuation, F5–F15, the whole keypad — never reached `OnKeyDown`, so `IsPressed(DIK_G)` and the Python `app.IsPressed` bindings were silently dead on Linux.
  - `Input.h` was not self-contained (it needed `HRESULT`, `HWND`, `LPDIRECTINPUT8` from the includer) and exposed the DirectInput member types.
  - `grep -rn "DirectInput8Create" src` → `include/Platform/DirectXMathCompat.h` (the compat stub, `Input.cpp` was its only caller).
  - Windows could only see `DIK_*` through `<dinput.h>` in `StdAfx.h`/`DirectXMathCompat.h`, because the block lived in `Platform.h`'s non-Windows branch.
  - `ctest`: 44/44.
- after:
  - `Input.cpp` is SDL2-only on every target: a **134-entry SDL scancode → DIK table** (26 letters, 10 digits, 12 number-row symbols, keypad in physical grid order, modifiers, navigation, F1–F15, media/browser keys, ISO `OEM_102`, Japanese `YEN`/`KANA`/`KANJI`), edge events diffed from the SDL keyboard-state array, and focus-loss release when `SDL_GetKeyboardFocus()` is `NULL`.
  - `Input.h` is self-contained, keeps the historical `InitializeKeyboard(HWND)` signature (the handle is unused; `CPythonApplication` is unchanged), and exposes `ScancodeToDik()` + `UpdateKeyboardFromState()` for headless tests.
  - `grep -rn "DirectInput8Create" src` → **empty** (16 `DirectXMathCompat.h` copies lose the stubs).
  - `DIK_*` moved out of `Platform.h`'s Linux branch in all 16 packages; it stays behind `#ifndef DIK_ESCAPE`, so a real `<dinput.h>` still wins where it is included. `dinput.h` now remains only in legacy headers (`StdAfx.h`, `DirectXMathCompat.h` — T1.5/T4.1) and the `UserInterface.cpp` link pragma (T4.1).
  - `ctest`: **45/45** (`test_input` added; 6 sections: table uniqueness/coverage, letters+digits, named keys, navigation+keypad, edge events, focus loss).
  - `scripts/golden-check.sh`: **11/11** — render hashes, Python API surfaces, pack/model/collision/packet transcripts, CTest inventory (refreshed for `test_input` only).
  - Windows probe: `x86_64-w64-mingw32-g++` compiles `Input.cpp` and syntax-checks `test_input.cpp` against the SDL2 headers, with `OPENMT2_PLATFORM_WINDOWS` and a minimal `StdAfx.h` shim (the real one still pulls `<directxsdk/d3dx9.h>`, T4.1).
- notes:
  - PRs: open-mt2/pkg_eterlib#10 (implementation + tests), plus one header-only PR per package: pkg_eterbase#12, pkg_eterlocale#5, pkg_eterpack#5, pkg_eterimagelib#5, pkg_spherelib#5, pkg_cwebbrowser#4, pkg_mileslib#7, pkg_etergrnlib#6, pkg_speedtreelib#5, pkg_prterrainlib#5, pkg_effectlib#7, pkg_scriptlib#6, pkg_eterpythonlib#6, pkg_gamelib#5, pkg_userinterface#10.
  - **DIK↔SDL audit (task scope):**
    - keyboard — 134 physical keys mapped; the old path had 44. Mapping is physical (SDL scancode/USB HID position), so non-US layouts are covered by construction (AZERTY `Q` and QWERTY `A` share scancode 4 → `DIK_A`).
    - keypad — mapped in hardware grid order (`KP_1..KP_9` in SDL vs `NUMPAD7/8/9` top row in DIK); numlock state is not consulted, matching DirectInput.
    - mouse buttons — handled in `MSApplication.cpp` (T1.2) as `WM_LBUTTON*/RBUTTON*/MBUTTON*`; `SDL_BUTTON_X1/X2` are unmapped and unused by the client.
    - wheel — `SDL_MOUSEWHEEL` → `WM_MOUSEWHEEL` at 120 units/notch (T1.2). `SDL_MOUSEWHEEL_FLIPPED` is ignored; recorded as a T3.3 parity-audit item.
    - focus loss — old DirectInput path returned early when `GetDeviceState` failed, leaving keys stuck down; the new path releases every held key exactly once.
  - Deviations: `SDL_SCANCODE_WAKE`/`AUDIOMUTE`/`AC_HOME` are left unmapped because the image's SDL 2.26 lacks `WAKE` and the others would collide with `DIK_WEBHOME`/`DIK_MUTE`; `DIK_ABNT_C1/C2` and `DIK_CONVERT/NOCONVERT` have no unambiguous SDL equivalent and are never read by the client.
  - The EterBase checkout carried unrelated, uncommitted T1.7 work (`RenderBackend.h`, `src/backends/`, `test_render_seam.cpp`, plus T1.7 edits inside the two platform headers). Those changes were preserved untouched and are **not** part of T1.3; the EterBase header commit was prepared in a throwaway worktree from `origin/main`.
  - Follow-ups: T3.3 should check `SDL_MOUSEWHEEL_FLIPPED` and the X1/X2 buttons; T1.6 owns text input (SDL_TEXTINPUT already feeds `WM_CHAR`); T1.5/T4.1 can now drop `<dinput.h>` entirely.
