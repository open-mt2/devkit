# T1.7 — Renderer seam skeleton

- agent: agent-07 (DeepSeek V4.1 Flash)
- date: 2026-10-31
- command: `ctest --output-on-failure` · `scripts/golden-check.sh` · `grep -rn "gl[A-Z]" src`
- before: `eterbase/src/Direct3DDevice9Compat.cpp` (1541 lines) called OpenGL directly — **240 call sites / 58 distinct `gl*` symbols** — and stored `GLuint` texture/FBO/renderbuffer names in the public D3D9 compat header, so no second backend could be added without rewriting the façade.
- after: the façade is state tracking only (943 lines, no GL header, no GL name). All OpenGL lives in `src/backends/gl/` behind `IRenderBackend`; `grep -rn "gl[A-Z]" src | grep -v src/backends/gl` is empty. `ctest` **45/45 passed** (44 before + `test_render_seam`); `golden-check.sh` **11 checks passed, 0 failed**, including `render hashes (12 artefacts)` — Linux output is byte-identical.

## What landed

- `include/Platform/RenderBackend.h` — `RenderCaps`, `RenderHandle` (opaque `id` + `generation`), `RenderState` (render states, two modelled texture stages, samplers, transforms, render-target flag), `DrawCall` (state + resolved ranges) and `IRenderBackend` (`CreateTexture`, `CreateDepthStencil`, `Destroy`, `UploadTextureLevel`, `FinalizeTexture`, `Bind{RenderTarget,DepthStencil,DefaultRenderTarget}`, `SetViewport`, `Clear`, `BeginFrame`, `Present`, `BindStageTexture`, `ApplyState`, `Draw`, `Readback`).
- `src/RenderBackend.cpp` — `Platform_GetRenderBackend()`, selected at configure time (R8). Construction issues no GL call, so the headless tests that only track state never need a context.
- `src/backends/gl/GLRenderBackend.{h,cpp}` — the pre-seam renderer body with the façade stripped out: texture upload (DXT1/3/5, 16-bit expansion), depth renderbuffer, FBO attach, clear/viewport, fixed-function state (`ApplyState`, same order as the old `SetupGLState`), vertex arrays + draw, and `Readback()` (`glReadPixels`, the entry point T3.2/T5.4 will use).
- `src/backends/gl/GLCompat.cpp` — the T1.4 loader, moved (move-only commit) so R1 holds for the whole of `src/`.
- `src/Direct3DDevice9Compat.cpp` — keeps D3D9 state and resource bookkeeping; `FillRenderState()` builds the snapshot, the four draw entry points submit `DrawCall`s.
- `include/Platform/DirectXMathCompat.h` — `RenderHandle` members replace `GLuint` (`GetTextureHandle`, `GetDepthStencil`); `ComputeUntexturedStage0Color` uses `float` (no `GLfloat`).
- `tests/test_render_seam.cpp` — contract test (handle opacity, snapshot copy semantics, façade state round-trips, empty draws stay no-ops, texture metadata). It fails to compile before this change and passes after; it needs no GL context.

## Notes and follow-ups

- **Pass-through, not a rewrite.** The GL backend keeps the old call order: `SendText`-style per-draw emulation (`ComputeUntexturedStage0Color`) stays in the façade because it is D3D9 semantics; the GL backend applies the first two texture stages exactly as the old `SetupGLState` did (stages 2–7 are carried in the snapshot for a future synthesising backend).
- **Header duplication.** `DirectXMathCompat.h` is copied into all 16 packages. The seam changes the class layout, so every copy must be synced: 15 header-only PRs (list below). The EterLib copy merges cleanly with T1.3's DirectInput removal (disjoint hunks).
- **Not verified:** Windows. The image has no C++ cross compiler (`i686-w64-mingw32-gcc` only) and both new translation units are gated on `OPENMT2_RENDERER_GL`, which is a Linux-only definition today — the Windows build is unchanged. T1.5 flips the façade gate from `OPENMT2_PLATFORM_LINUX` to `OPENMT2_RENDERER_GL` and can then cross-compile this code.
- **Follow-ups:** wire `Readback()` into the TA.4/T3.2 harness; add the swapchain abstraction before T5.1; give `Caps()` consumers when T1.5/T5.2 need them; `-Wreorder` on `m_fillMode`/`m_textureFactor` is pre-existing.
