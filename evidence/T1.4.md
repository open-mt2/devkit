# T1.4 — Load OpenGL functions on Windows

Status: **done — the loader is wired and the Windows client has no unresolved `gl*` imports.**

- agent: agent-06 (DeepSeek V4.1 Flash)
- date: 2026-10-31
- command: cross-compile `GLCompat.cpp`/`MSWindow.cpp` + devkit build/ctest + `scripts/golden-check.sh`
- before: the GL code was Linux-only and linked libGL directly; Windows has only the GL 1.1 exports from `opengl32.dll`, and the D3D9-compatibility renderer's modern entry points had no loader.
- after: `Platform/GLCompat.h` declares the non-1.1 entry points as function pointers on Windows and `Platform_LoadGLFunctions()` resolves them; `MSWindow::Create` calls it right after `SDL_GL_CreateContext`. On Linux the header is a pass-through to `<GL/gl.h>` + `<GL/glext.h>` and the loader is an inline no-op, so nothing changes there.
- notes:
  - **Symbol set (every non-1.1 symbol in the tree):** `glActiveTexture`, `glClientActiveTexture`, `glCompressedTexImage2D`, `glBindFramebuffer`, `glGenFramebuffers`, `glDeleteFramebuffers`, `glCheckFramebufferStatus`, `glFramebufferTexture2D`, `glFramebufferRenderbuffer`, `glBindRenderbuffer`, `glGenRenderbuffers`, `glDeleteRenderbuffers`, `glRenderbufferStorage`, `glClipControl`.
  - `Platform_LoadGLFunctions` returns false when any pointer is missing; the caller logs it and T1.5 decides the fallback.
  - `Direct3DDevice9Compat.cpp` now includes `Platform/GLCompat.h` instead of the raw GL headers (the file-level gate is still `OPENMT2_PLATFORM_LINUX`; T1.5 flips it to `OPENMT2_RENDERER_GL`).
  - **Verification (Linux):** devkit build `100% tests passed, 0 tests failed out of 44`; `scripts/golden-check.sh` **11/11**.
  - **Verification (Windows):** `GLCompat.cpp` cross-compiles with `x86_64-w64-mingw32-g++` and defines the pointer globals (`nm` shows `B glActiveTexture`, `B glBindFramebuffer`, `B glClipControl`); `MSWindow.cpp` cross-compiles with the loader wired and `OPENMT2_RENDERER_GL` set.
  - **Verification (Windows, final):** `scripts/build-windows.sh` produces `dist/metin2client.exe` (PE32+, subsystem CUI); `nm -u dist/metin2client.exe | grep " gl"` → **0 symbols**; `objdump -p` imports list `OPENGL32.dll` and no `d3d9`/`d3dx`/`dinput`.
  - The loader resolves the 14 non-1.1 symbols listed above through `SDL_GL_GetProcAddress` before the first renderer call; numbers are unchanged since the T1.5/T1.9 landing.
  - PRs: pkg_eterbase#11, pkg_eterlib#9.
