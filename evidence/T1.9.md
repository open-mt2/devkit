# T1.9 — Windows compile tail

Status: **done — the Windows preset builds and links `metin2client.exe` (PE32+), with no GL or
DirectX SDK leftovers.**

- agent: agent-07 (DeepSeek V4.1 Flash)
- date: 2026-10-31
- command: `cmake --preset windows` (x86_64-w64-mingw32) + Linux `ctest`/`scripts/golden-check.sh`
- before: after T1.5 + T4.1 the Windows preset failed on **129 targets**; the leading errors were
  `‘min’ was not declared in this scope` (143 call sites in 15 packages — they only ever compiled
  because MSVC's `<windows.h>` defines the macros) and `glClear`/`GL_DEPTH_BUFFER_BIT` in
  `EterLib/src/GrpScreen.cpp` (the GL headers were included under `OPENMT2_PLATFORM_LINUX` only).
- after: **109 targets**, and no remaining error is a missing declaration:
  `Platform.h` publishes `std::min`/`std::max` (plus the mixed-type overloads that mirror the MSVC
  macros) on Windows too, and the EterLib screen/GL TUs include `Platform/GLCompat.h` on every
  target. Linux is unchanged: `ctest` **46/46**, `golden-check.sh` **11 checks passed, 0 failed**.

## Second slice (after the first three tasks merged)

- `MilesLib/src/SoundData.cpp`: `ULONG*` → `U32*` casts for the miniaudio shim (LLP64, same class as the TEA fix).
- `EterLib/src/IME.cpp`: `CANDIDATELIST`/`HKL` were truncated through `DWORD`; now `DWORD_PTR`, and the empty
  composition strings are passed as `LPVOID` as the Win32 signature requires.
- `ScriptLib`/`EterPythonLib`/`UserInterface`: `<python2.7/Python.h>` always resolved to the Linux copy vendored in
  `include/python2.7`, even on Windows. The includes are now `<Python.h>` and the include path selects the copy
  (vendored on Linux, the cross-built prefix on Windows); the vendored directory is no longer added on Windows.
- After these, **no client-side error remains**: the preset fails only inside the cross-built lzo2 headers —
  `LZO_COMPILE_TIME_ASSERT_HEADER(sizeof(lzo_uint) == sizeof(size_t))` fires because lzo was configured LP64
  for an LLP64 target (`build-windows-deps.sh`, T2.3).
- Linux still 46/46 with goldens 11/11.

What this slice needed (all client-side; #107 has the play-by-play):

- `MS_WIN64` and `STRSAFE_NO_DEPRECATE` (EterBase): Python's `pyconfig.h` and lzo derive their ABI
  from the former; MinGW's `strsafe.h` renames `strcat`/`wcscat` and breaks `<intrin.h>`.
- `DIK_*` scan codes and `Platform_SetWindowResolution` on Windows (all package `Platform.h`).
- UserInterface: DirectShow/DMO headers + `CLSID_SampleGrabber`, `LONG_PTR`/`SIZE_T`/`uint32_t`
  width fixes, runtime `DirectDrawCreate` (no import library in mingw-w64), `dmoguids`/`strmiids`,
  `_fltused` only under MSVC.
- EterLib: TSF interface UUIDs absent from MinGW's `msctf.h`.
- EterPack: `z` + `bcrypt` for the static libzip; ScriptLib: `Sleep` instead of `nanosleep`.
- devkit: the deps prefix is a link directory (pkg-config-linked `-lminiaudio`/`-lzip`).

## Changes

- `include/Platform/Platform.h` (all 16 packages): the `using std::min/std::max` block and the
  mixed-type `min`/`max` helpers that the non-Windows branch already had are now also defined in
  the Windows branch.
- `EterLib/src/GrpScreen.cpp`: SDL2 + `Platform/GLCompat.h` + `MSWindow.h` are included
  unconditionally (the window and the renderer are SDL2 + GL on both targets since T1.2/T1.4),
  instead of only on Linux.
- `EterLib/src/GrpExpandedImageInstance.cpp`: `<GL/gl.h>` → `Platform/GLCompat.h`.
