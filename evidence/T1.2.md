# T1.2 — SDL2 window and event loop on both targets

Status: **done — SDL-only window and event loop on both targets; the window opens under Wine.**

- agent: agent-06 (DeepSeek V4.1 Flash)
- date: 2026-10-31
- command: `grep -rn "CreateWindowEx\|CreateWindow\|RegisterClass" src` + devkit build/ctest + cross-compile of `MSWindow.cpp`/`MSApplication.cpp`
- before: `MSWindow.cpp`/`MSApplication.cpp` kept the Win32 path in `#else` branches (`CreateWindow`, `RegisterClass`, `MSWindowProcedure`, `PeekMessage`/`GetMessage`); the SDL path was compiled only when `OPENMT2_PLATFORM_LINUX` was defined.
- after: both files are SDL-only on every target; the Win32 window creation, class registration, window procedure and message loop are deleted. WM_* messages are still synthesised from SDL events, so `WindowProcedure` stays as the dispatcher.
- notes:
  - `MSWindow.h` includes `<SDL2/SDL.h>` directly and always exposes the SDL members; `EterLib` finds and links `SDL2::SDL2` on every target (the T2.3 prefix provides it for Windows).
  - The GL context setup (`SDL_GL_SetAttribute`, `SDL_GL_CreateContext`, `glClipControl`, the initial clear) is gated on `OPENMT2_RENDERER_GL`; without it the window is created plain. Windows stays on the D3D9 path until T1.5.
  - `include/EterLib/SdlPlatform.h` provides the SDL window-state helpers on Windows, because `Platform.h` defines them only in its Linux compatibility branch (the Windows branch is the real Win32 API). TB.3 removes the duplication.
  - `WM_CLOSE` now sets `Platform_GetQuitRequested()` instead of calling `PostQuitMessage`, which is a real Win32 API on the Windows target.
  - `GL_LOWER_LEFT` gets a fallback define: the Windows GL headers only ship the 1.1 subset until T1.4 adds the loader.
  - **Verification (Linux):** devkit build `100% tests passed, 0 tests failed out of 44`; `scripts/golden-check.sh` **11/11**.
  - **Verification (Windows, final):** `grep -rn "CreateWindowEx" src` → **0** matches. `scripts/build-windows.sh` links `metin2client.exe` (PE32+); under Xvfb + Wine the process stays alive for the full 35 s observation window with the window mapped (screenshot: `evidence/T1.2-wine-window.png`). `syserr.txt` has one non-fatal `CMSWindow::Cursors Create Error`; no window/event-loop error.
  - The smoke used the `winx64` toolchain image with `wine64` installed and the T2.3 prefix mounted at `/opt/openmt2/win64`; the Dockerfile now installs `wine64`/`xauth` so the canonical image can run the same smoke.
  - **Not done (moved to T3.1):** `build-windows.sh` copies `bin/pack/Index` but no archives; `bin/pack/` holds unpacked directories that only `build.sh` (Linux) zips. For the smoke, the 107 archives were packed into `dist/pack/` manually.
