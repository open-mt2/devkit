# T2.2 — Audit libjpeg usage and document its disposition

- agent: agent-06 (DeepSeek V4.1 Flash)
- date: 2026-10-31
- command: `grep -rn "jpeglib\|jpeg_" src` + devkit build/ctest + `scripts/golden-check.sh`
- before: libjpeg was linked into EterLib (`find_package(JPEG REQUIRED)`, `JPEG::JPEG`) and used only by `src/JpegFile.cpp`; the sole caller was `CPythonGraphic::SaveJPEG` (screenshots, quality 85, **BGR** buffer). `jpeg_load`, `jpeg_load_from_mem`, `jpeg_save_to_file` and `jpeg_save_to_mem` had no callers.
- after: libjpeg is no longer referenced by any CMakeLists or source; screenshots are written through `Platform_SaveImageJPEG` (`stb_image_write`, already vendored in T2.1).
- notes:
  - **Disposition: replace (D5 revised).** One writer call site, no progressive/quality requirement beyond 85, and it removes a dependency T2.3 would otherwise have to cross-build for the Windows target. `stb_image_write` is baseline JPEG only, which is enough for screenshots.
  - **Pre-existing bug fixed:** `JpegFile.cpp` set `in_color_space = JCS_RGB` while the screenshot buffer is BGR (the `SaveScreenShot` switch writes Blue, Green, Red), so saved screenshots had red and blue exchanged. `jpeg_save` now converts BGR → RGB before writing.
  - **API:** only `jpeg_save` remains in `EterLib/JpegFile.h`; the four unused entry points are gone.
  - **Test:** `tests/test_jpeg.cpp` saves an 8×8 half-red/half-blue BGR buffer, decodes it back through `Platform_DecodeImage` and asserts the channel order (tolerance 60 for JPEG). Against `origin/main` the test fails at `left[2] > 190` (the swap); with the change it passes.
  - Verification (devkit image `openmt2/client:79`, host `src/` mounted): **44/44 ctest**, `scripts/golden-check.sh` **11/11**. Only `golden/ctest-tests.txt` changed (`test_jpeg` added); render hashes, render goldens, Python API and transcripts are unchanged.
  - PRs: pkg_eterbase#9, pkg_eterlib#7. Merged with the package workflows disabled (main-only policy, #93), so no CI runs were spent.
  - Follow-up: `libjpeg-dev` can be dropped from the devkit image once nothing else pulls it (DevIL already removed in T2.1); T2.3 no longer needs a libjpeg cross-build.
