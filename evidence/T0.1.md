Note: mounting the host `src/` into `/workspace/src` is not equivalent to the
image snapshot — the Dockerfile injects the vendored `Platform/stb_image.h` at
build time, so a host-source build fails to compile `ImageLoaderCompat.cpp`
(missing header) before any test runs. The documented `build/`+`dist/`-only
mounts are the correct reproduction for the native suite.

The earlier host-only run (2/3, `test_real_build_failure_and_success_are_distinguished`
failing with `2 != 0`) was a missing-host-prerequisite artifact: neither `cmake`
nor `ninja` existed on the host. With both present in the container the full
CLI suite passes with no source or assertion changes.

Host follow-up: `cmake` and `ninja` were then installed locally via Homebrew
(CMake 4.4.5, Ninja 1.13.2 — newer than the image's 3.25.1/1.11.1). The same
host command now passes **3/3 OK**, confirming the failure was prerequisite-only
and not sensitive to the exact tool versions:

```bash

```
