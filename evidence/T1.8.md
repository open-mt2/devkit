- before: no script and no matrix. The plan counted **68 `D3DRS_*` / 25 `D3DTSS_*`** with a raw grep over `src/`, which includes comments, the 16 vendored `DirectXMathCompat.h` copies and API declarations, so it over-counted what the app actually asks for. - after:
  - `scripts/feature-matrix.py` (generator) + `scripts/feature-matrix.sh` (`--write` / `--check`), checking in `docs/planning/feature-matrix.md`.
  - Generated matrix, from comments/strings-stripped sources, excluding `tests/` and the platform implementation (`include/Platform/`, `EterBase/src/`):
    | Item | Distinct | Call sites |
    |---|---:|---:|
    | Render states (`D3DRS_*`) | 51 | 212 |
    | Texture-stage states (`D3DTSS_*`) | 9 | 439 |
    | Sampler states (`D3DSAMP_*`) | 6 | 66 |
    | Transform states (`D3DTS_*`) | 5 | 49 |
    | FVF layouts | 17 | 52 |
    | Shader calls (no-op on GL) | 10 | 37 |
    | **Total** | **71** | **766** |
  - FVF layouts are expanded to their `D3DFVF_*` value, including `static DWORD`/`#define` aliases and `D3DFVF_TEXCOORDSIZE*` packing (e.g. `D3DFVF_SPEEDTREE_LEAF_VERTEX` → `0x150142`); dynamic `SetFVF(variable)` rows are marked `—`.
  - Texture-stage table records stages 0–7 plus the variable-stage loops, so T5.2 knows the real stage count.
  - `CShaderStats` (`EterLib/include/EterLib/ShaderStats.h`, `src/ShaderStats.cpp`) counts created/bound vertex and pixel shaders, constant uploads and the ignored shader file set, and logs one line per ignored file (D13). Hooks: `CVertexShader::CreateFromDiskFile`, `CPixelShader::CreateFromDiskFile`, `CStateManager::{Set,Save}Vertex/PixelShader[Constant]` path.
  - `tests/test_shader_stats.cpp`: creation/dedup, binds, uploads, reset.
  - `feature_matrix` is registered as a CTest case in the root `CMakeLists.txt` (`BUILD_TESTS`), so drift fails `ctest` as well as the explicit check.
  - `ctest`: **47/48** (new `test_shader_stats`, new `feature_matrix`; all pass except `render_golden`, see the T1.7 note below); `scripts/feature-matrix.sh --check`: current.
