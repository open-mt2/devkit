# T3.2 — Automated smoke test

- agent: agent-06 (DeepSeek V4.1 Flash)
- date: 2026-10-31
- command: `scripts/smoke.sh windows && scripts/smoke.sh linux` (inside `openmt2/client`, Xvfb + Wine)
- before: there was no boot check. The Windows client never reached a working
  window in CI-able conditions: it stopped at a `CREATE_CURSOR` message box
  (no Win32 cursor resources ship with the sources), and once past that it
  rendered nothing (`RenderFPS: 0`) because `m_isMinimizedWnd` started `true`
  and Wine never sends the initial `WM_SIZE`. There was also no screenshot or
  black-screen signal to catch this.
- after: `scripts/smoke.sh` boots the packaged tree headlessly, waits, captures
  a screenshot and fails on early exit, fatal `syserr.txt` lines, or a blank
  screen. Both targets pass: **linux 87 629 colours**, **windows 121 colours**,
  both showing the `Choose Server` login dialog.
- notes:
  - **Two real fixes fell out of the smoke** (package PR
    open-mt2/pkg_userinterface#18):
    - `CreateCursors` now uses SDL system cursors (`SdlCursor.h`) instead of
      `LoadImage(IMAGE_CURSOR)` — the resource script is not in the tree, so
      the Windows client always failed earlier.
    - `ShowCursor` must be called once: SDL returns the previous 0/1 state,
      not the Win32 reference counter, so the existing do/while loop hung the
      process at 100 % CPU.
    - `m_isMinimizedWnd` starts `false` on every target (the SDL window is
      created shown); this is what kept the Windows render loop at
      `RenderFPS: 0`.
  - **Script behaviour:** picks the binary by target (`metin2client` /
    `metin2client.exe`), starts its own Xvfb, runs `wineboot -u` before the
    first Wine run, and uses `--settle` (25 s Linux / 35 s Windows). Failures:
    non-zero/early exit, `RunMain Error`/`Failed to initialize Python`/`FATAL
    ERROR` in `syserr.txt`, fewer than `--min-colors` distinct colours.
    `--home` moves the Wine prefix (use a tmpfs when disk is tight) and
    `--reference` diffs the screenshot with `render-diff.py`.
  - **Image prerequisites:** `wine64`, `xauth`, `imagemagick` (for `import`/
    `convert`) were added to the Dockerfile; the prefix is removed after a run
    unless `--keep` is passed (it is ~1 GB).
  - Tests: `tests/test_smoke_script.py` **5/5** (help, bad target, missing
    dist, Wine requirement, documented flags).
  - **Known parity gap (T3.3):** the Linux screenshot shows the full login
    artwork; the Windows one shows the same dialog on a black background, so
    the login background scene does not render under Wine. The smoke passes
    on UI content, not on pixel identity.
