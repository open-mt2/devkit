# T1.6 — IME / text input

- agent: agent-06 (DeepSeek V4.1 Flash)
- date: 2026-10-31
- command: `ctest -R ime` + full `ctest` + `cmake --preset windows` + `scripts/smoke.sh windows`
- before: the only live implementation was the Windows IMM/TSF path in
  `EterLib/src/IME.cpp` (2384 lines, `msctf.h` + `Dimm.h`). The Linux branch was
  a stub with no text input at all, and neither target consumed SDL's text
  events. There was no `ime` test.
- after: one SDL-backed implementation for both targets
  (`EterLib/src/IME_Sdl.cpp`). `SDL_TEXTEDITING` updates the composition buffer
  and `SDL_TEXTINPUT` commits UTF-8 text into the buffer the Python `ime`
  module reads. The legacy IMM/TSF file is compiled only for a non-SDL Windows
  build and no longer includes `Dimm.h` from the live header. `ctest -R ime`
  exists and passes.

## Behaviour

| API | SDL implementation |
|---|---|
| Composition | `SDL_TEXTEDITING` → `GetCompLen`, `GetULBegin`, `GetULEnd` |
| Commit | `SDL_TEXTINPUT` appends UTF-8 to the text buffer, `GetText` returns it |
| `SetText` / `GetText` / cursor | UTF-8 buffer with insert/delete semantics matching the old tests |
| Number mode / except keys | enforced in `OnChar` |
| Paste | `SDL_GetClipboardText` |
| Candidate list / reading window | **not available** — SDL exposes neither, so the getters return 0/empty. Documented limitation. |

## Notes / limitations

- The buffer is UTF-8 (`GetCodePage` returns 65001). The old path converted to
  the locale code page; with SDL the platform IME already delivers UTF-8.
  A CJK client that expects CP949/CP932 bytes would need a conversion layer.
- The candidate/reading window is provided by the OS IME, not by the client;
  none of the candidate-list screens are driven from the game.
- A real CJK input test needs a desktop IME (IBus/Fcitx on Linux, a system IME
  on Windows) and was not possible headlessly; T3.3 records this as the
  remaining unverified item.
