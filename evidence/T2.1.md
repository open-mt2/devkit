# T2.1 — Remove the DevIL dependency

- agent: agent-06 (DeepSeek V4.1 Flash)
- date: 2026-10-31
- command: `grep -rn "IL/il.h\|target_link_libraries.*IL" src` + devkit build/ctest + `scripts/golden-check.sh`
- before: DevIL was used by `MarkImage.h/.cpp`, `GuildMarkUploader.h/.cpp`, `PythonApplicationModule.cpp`, `UserInterface.cpp` (`ilInit`) and the `__UNITTEST__` helper in `MarkManager.cpp`; `IL` was an unconditional link library in `UserInterface/CMakeLists.txt`.
- after: **0** IL includes or link entries in `src/`; the only textual match was a historical README line, now updated.
- notes:
  - **New writer in EterBase:** `Platform_SaveImageTGA(path, w, h, bgra)` wraps `stb_image_write` (`include/Platform/stb_image_write.h`, public domain). Input is BGRA; the helper swaps to RGBA because that is what `stb_image_write` expects for TGA. `Platform_DecodeImage` already provided the reader side.
  - **`CGuildMarkImage`** now owns a `std::vector<BYTE>` BGRA buffer: `Build`/`Save` → `Platform_SaveImageTGA`, `Load` → `Platform_DecodeImage`, `PutData`/`GetData` → row copies. The DevIL image handle and the unused `m_apxImage` array are gone.
  - **Data-width fix (T0.3 follow-through):** `Pixel` was `unsigned long` (8 bytes on LP64). That made `SGuildMark::m_apxBuf` 1536 bytes instead of 768, so `IsEmpty()`/`GetEmptyPosition()` scanned uninitialised bytes and the LZO block sizes no longer matched the 16×12×4 wire format. It is now `uint32_t` with a `static_assert(sizeof(Pixel) == 4)`.
  - **Call sites:** `GuildMarkUploader::__Load`/`__LoadSymbol`, `appGetImageInfo` and the `__UNITTEST__` helper use the new `ImageFile` helper (`GetImageFileInfo`/`LoadImageFileBGRA`); the dead IL block in `__Save` and `ilInit()` are removed.
  - **Test:** `tests/test_mark_image.cpp` builds an image, saves a TGA, reloads it, compares the mark pixels byte-for-byte and checks `GetEmptyPosition()`; it also pins an untouched slot as empty. It must allocate `CGuildMarkImage` on the heap (the object embeds ~3 MB of blocks) and create the `CLZO` singleton the client creates in `main`.
  - Verification (devkit image `openmt2/client:79`, host `src/` mounted): **43/43 ctest**, `scripts/golden-check.sh` **11/11**. Only `golden/ctest-tests.txt` changed (`test_mark_image` added); render hashes, render goldens, Python API and the pack/model/collision/packet transcripts are unchanged.
  - PRs: pkg_eterbase#8, pkg_userinterface#7 (code) and pkg_userinterface#8 (docs). Merged with the package workflows disabled (main-only policy, #93), so no CI runs were spent.
  - Follow-up: the same `unsigned long` width issue exists in the SpeedTree colour storage documented by T0.3; that stays with its own task.
