- before: the Windows build pulled the DirectX SDK, Miles and the SpeedTree import library from headers and MSVC pragmas — 8 files across 4 packages:
  ```
  EterLib/include/EterLib/{Ray,Util,StdAfx,StateManager,GrpDetector}.h  → <directxsdk/d3dx9.h>, <d3d9.h>, <dinput.h>
  ```

  `cmake --preset windows` failed with 234 targets, `directxsdk/d3dx9.h: No such file or directory` leading.
- after: `grep` matches only two explanatory comments; the Windows preset fails on 129 targets whose errors are ordinary portability issues (`min`/`max` unqualified, direct GL calls in `EterLib/src/GrpScreen.cpp`), tracked in #107.
  Linux is unchanged: `ctest` **46/46 passed**, `golden-check.sh` **11 checks passed, 0 failed**.

## Changes

- EterLib: five headers now include the compatibility vocabulary on every target instead of the SDK.
- SphereLib: same in `StdAfx.h`.
- MilesLib: `MSSCompat.h` (miniaudio) is the only sound backend; Miles is gone.
- UserInterface: the MSVC `#pragma comment(lib, …)` block is deleted. `_fltused` and the
  `NvOptimusEnablement`/`AmdPowerXpressRequestHighPerformance` exports stay (they select the
  discrete GPU and are part of the shipped binary's contract).
- EterBase: `imagehlp` and `ws2_32` move to the CMake link line, where the pragmas used to put them.

## Notes

- Stacked on `task/T1.5-windows-gl`: the sheet lists T1.5 as T4.1's dependency, and the two must
  merge in that order (T1.5 carries the compat-header sync this change relies on).
- `#include <d3d9.h>` remains only inside the `_WIN32 && !USE_PLATFORM_D3D_COMPAT` branch of
  `DirectXMathCompat.h`, i.e. the legacy native path that D1/D2 retired; removing that branch
  belongs with the TB.1 header consolidation, not here.
- The `_access` call in `EterPackManager.cpp` needed `<io.h>` on Windows; added under `_WIN32`.
