## Changes

- `pkg_eterbase`:
  - `src/Direct3DDevice9Compat.cpp` — gate `OPENMT2_PLATFORM_LINUX` → `OPENMT2_RENDERER_GL` (R8: the renderer picks the TU, not the OS).
  - `CMakeLists.txt` — Windows defines `OPENMT2_PLATFORM_WINDOWS`, `OPENMT2_RENDERER_GL`, `OPENMT2_SDL_WINDOW`, `USE_PLATFORM_D3D_COMPAT`; links `opengl32` and `winmm`; `find_package(OpenGL)` only for host builds.
  - `include/Platform/DirectXMathCompat.h` — `<d3dx9.h>`/`<dinput.h>` dropped from the legacy branch; `MAKEFOURCC` defined locally (the DXT formats depend on it).
  - `include/Platform/GLCompat.h` — the GL 1.3/EXT enums a Windows GL 1.1 header lacks (`GL_TEXTURE1..7`, `GL_TEXTURE_MAX_LEVEL`, `GL_FRAMEBUFFER`, `GL_RENDERBUFFER`, `GL_COLOR_ATTACHMENT0`, `GL_DEPTH_ATTACHMENT`, `GL_DEPTH_COMPONENT16`).
  - 15 packages: identical `DirectXMathCompat.h` sync.
- `devkit`: `dockerfile` adds `gcc-mingw-w64-x86-64` (it listed only the C++ half, so the C compiler the toolchain file wants was never installed).

## Why the task is not closed

`docker run --rm openmt2/client windows` cannot pass in the current image, for
reasons unrelated to the renderer (issue #107):

1. the running image predates the dockerfile's MinGW lines and has no
   `/opt/openmt2/win64` (T2.3 deps) — the dockerfile fix needs an image rebuild;
2. `src/EterLib/CMakeLists.txt:52` needs an `SDL2Config.cmake` the dep script
   does not install;
3. `src/error.cpp:50` reads 32-bit `CONTEXT.Eax` fields (D10 = 64-bit);
4. `MappedFile.cpp`/`lzo.cpp` need the cross-built lzo headers on the include path.

The renderer half is done: it compiles, links, and imports nothing from the
DirectX SDK.
