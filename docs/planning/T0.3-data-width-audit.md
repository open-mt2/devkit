# T0.3 — Pack, mesh, and treecache data-width audit

**Decision:** D10 selects 64-bit Linux and 64-bit Windows. The target ABIs are
LP64 on Linux (long, pointers, and size_t are 64-bit) and LLP64 on Windows
(long is 32-bit; pointers and size_t are 64-bit). A Windows long is not a
portable on-disk 64-bit integer.

**Scope:** the current EterPack ZIP/folder providers, clean-room GR2 reader and
runtime model structures, and SpeedTree baked-tree reader. No source behavior
was changed in this task. Source references below are pinned to the package
revisions recorded in evidence/T0.3.md.

The broad task-sheet scan is intentionally only an inventory: it finds many
size_t uses in container loops and duplicated platform compatibility headers.
Those host-index uses do not imply an on-disk ABI. Review serialized fields,
file sizes, casts, and raw copies at the reader boundaries as above.

## Required compile-time guards

Add these guards with the follow-up source fixes, next to the formats/types they
protect. They pin the supported target and serialized contracts without
mistaking native runtime structs for file layouts.

    static_assert(sizeof(void*) == 8, "OpenMT2 targets are 64-bit");
    static_assert(sizeof(size_t) == 8, "OpenMT2 targets require 64-bit size_t");
    static_assert(sizeof(uint8_t) == 1 && sizeof(uint16_t) == 2 &&
                  sizeof(uint32_t) == 4 && sizeof(int32_t) == 4,
                  "serialized integer widths changed");
    static_assert(sizeof(float) == 4 && std::numeric_limits<float>::is_iec559,
                  "treecache and GR2 records require IEEE-754 binary32");
    static_assert(sizeof(TreeCacheColor) == 4,
                  "treecache colors are serialized as u32");
    static_assert(sizeof(granny_transform) == 68 &&
                  offsetof(granny_transform, Position) == 4 &&
                  offsetof(granny_transform, Orientation) == 16 &&
                  offsetof(granny_transform, ScaleShear) == 32,
                  "GR2 transform record layout changed");
    static_assert(sizeof(granny_tri_material_group) == 12 &&
                  offsetof(granny_tri_material_group, TriFirst) == 4 &&
                  offsetof(granny_tri_material_group, TriCount) == 8,
                  "GR2 material group record layout changed");

TreeCacheColor is a proposed fixed-width alias for the follow-up; the current
unsigned long color storage must be replaced before that assertion is added.
Do **not** add static_assert(sizeof(long) == 4): it would reject the selected
Linux target. Do not pin sizeof(size_t) inside a file format; it is permitted
for host indexing only.

## Characterization and limits

- The CTest run recorded in evidence/T0.3.md includes test_pack_formats,
  test_gr2_reader, test_grn_reference, and test_treecache and preserves their
  current outputs as the pre-fix characterization. This task changes only
  documentation and task state, so those inputs and reader implementations are
  unchanged after the audit.
- A host LP64 width probe and an x86_64 Windows LLP64 compile probe are recorded
  in the evidence. The project's configured Windows cross-build remains i686;
  the probe confirms compiler ABI widths only, not a 64-bit Windows package
  build or runtime parity.
- Follow-up fixes belong in the package repositories and should add a golden
  treecache color-width assertion/fixture before changing reader storage.
